# Agent Kickoff Prompt

The agent kickoff prompt is the canonical first message you paste to an AI coding
agent (Claude Code, Cursor, Copilot, Windsurf, Aider, etc.) so it sets up
VibeWarden correctly from a clean start. It is owned by the `vibew` binary and
regenerated on demand — it always matches the version of vibew you have installed.

## Why it exists

Every retro since v0.17.0 has traced agent failures back to a user's privately-kept
kickoff prompt that was out of date. The most recent case (qr-code-blackhole,
v0.18.1) had an agent invoke `bash deploy.sh` from inside the bundle — an
instruction that worked pre-ADR-088 but has been wrong since #1138 removed
`deploy.sh`. The agent had no way to know its instructions were stale.

Giving the prompt the same content authority as `llms-full.txt` (see CLAUDE.md
§Content authority) closes this permanently: the binary ships the prompt, the
binary regenerates it, and the website serves the same content via `llms-full.txt`
so URL-discoverable consumption stays in sync.

## How to generate it

**Dev flavor** (install + scaffold + dev loop):

```
vibew prompt-template --name <your-project> --describe "<your description>"
```

**Deploy flavor** (adds bundle + scp + ssh + healthcheck):

```
vibew prompt-template --deploy --name <your-project> --describe "<your description>" --domain <your-domain>
```

`--domain` is required when `--deploy` is set. The command fails with exit 1
rather than rendering a `<your-domain>` placeholder — the agent needs a real
domain to configure TLS.

The deploy flavor includes an architecture mismatch note in Step 6: if building
on Apple Silicon (linux/arm64) for an amd64 VPS, the agent must run
`vibew build --platform linux/amd64` before `vibew bundle`. `vibew bundle`
hard-fails (exit 1) on arch mismatch. This matches the behavior added in #1200.

The output is stdout-only, pipeable directly into a chat box:

```
vibew prompt-template --name myapp --describe "todo list app" | pbcopy
```

## Dev flavor sample (placeholder values)

```
# VibeWarden Agent Kickoff Prompt (vibew <version>)
#
# Generated by: vibew prompt-template --name <your-project> --describe "<your description>"
# Regenerate any time: vibew prompt-template --help

You are an AI coding agent setting up a new application with the VibeWarden
security sidecar. Follow each step in order. Do not skip steps or combine them.
These instructions are generated by vibew <version> and match that exact binary.

## Step 1 — Install vibew

  curl -fsSL https://vibewarden.dev/install.sh | sh

Verify: `vibew --version` should print a version string.

## Step 2 — Scaffold the project

  mkdir <your-project> && cd <your-project>
  vibew init --name <your-project> --describe "<your description>"

This creates vibewarden.yaml, .gitignore, AGENTS-VIBEWARDEN.md, and AGENTS.md.
Read AGENTS-VIBEWARDEN.md — it lists security features you must NOT reimplement.

## Step 3 — Add TLS

  vibew add tls --domain <your-domain>

## Step 4 — Write your application

Write your application code. Read AGENTS-VIBEWARDEN.md before writing any auth,
rate-limiting, or security logic — VibeWarden handles those at the sidecar layer.

## Step 5 — Start the dev loop

  vibew dev

The sidecar starts on localhost. Your app is proxied through it automatically.
```

## URL-discoverable copy

The same canonical content is included in `llms-full.txt` as
`## 21. Agent Kickoff Prompt` so agents that fetch
`https://vibewarden.dev/llms-full.txt` see the same instructions as `vibew
prompt-template` would print. The binary version of `vibew prompt-template` is
canonical — the `llms-full.txt` section is a static snapshot of the dev flavor.
