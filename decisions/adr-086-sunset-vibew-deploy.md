# ADR-086: Sunset `vibew deploy` — bundle-and-deploy-manually is the canonical path

**Date**: 2026-04-20
**Issue**: [#1051](https://github.com/VibeWarden/vibewarden/issues/1051)
**Status**: Accepted
**Supersedes**: — (builds on ADR-085; executes deferred clauses from ADR-082
and ADR-085; marks ADR-080 and ADR-081 as historical)

---

## Context

Four retros (see `~/notes/vibewarden/` and the user-memory file
`project_deploy_cost.md`) converged on the same finding: `vibew deploy` is the
single largest source of user friction in the product. Sixteen deploy bugs
have been logged across three retro cycles. Remote SSH orchestration —
rsync-ing compose files, invoking `docker compose` remotely, bootstrapping
OpenBao over SSH, remote health probes, remote arch checks — accounts for the
majority of the bug volume and the majority of the code surface area
(~4 900 LOC of orchestration + tests).

ADR-085 shipped `vibew bundle` (via #1044) as the replacement: a thin command
that produces a self-contained Docker Compose artifact (`docker-compose.yml`,
`vibewarden.yaml`, `.env`, `sample.env`, `deploy.sh`, `README.md`, optional
`image.tar`) under `.vibewarden/bundle/`. The user then runs
`scp`/`ssh`/`docker compose up -d` themselves, or invokes the generated
`deploy.sh` reference script. No remote orchestration by vibew.

ADR-085 explicitly deferred two cleanup tasks to this issue:

1. Deletion of the deploy orchestration surface
   (`deployapp.Service.Deploy`, `BootstrapSidecar`, `DeployMultiApp`,
   `Status`, `Logs`, `LogsMultiApp`, `OpenBaoBootstrapper`, `Detect`,
   `IsMultiApp`, `checkArchCompatibility`, the rsync image-transfer path).
2. The package rename `internal/app/deploy/` → `internal/app/bundle/`.
   ADR-082 independently deferred the same rename with reference to this
   issue. ADR-085 kept `deployapp.Service.Bundle` as the shared entrypoint
   so `vibew deploy --dry-run` could continue working as a fallback until
   the sunset landed.

Both #1044 and the ADR-082 strict-merge fix (#1053) are now merged. All
prerequisites are satisfied; this ADR describes how the sunset is executed.

## Decision

Sunset `vibew deploy` in the next minor release. Concretely:

1. **Delete** all deploy-only orchestration code listed in the "Deletions"
   section below.
2. **Rename** `internal/app/deploy/` → `internal/app/bundle/` in a single
   commit using `git mv`. Every surviving file keeps its contents unchanged
   except the package declaration (`package deploy` → `package bundle`) and
   one embedded string in `bundle.go` (the generated-file header
   `# Generated by vibew deploy` → `# Generated by vibew bundle`). Imports
   in `internal/cli/cmd/bundle.go` and any other consumer flip from
   `deployapp "…/internal/app/deploy"` to `bundleapp "…/internal/app/bundle"`.
3. **Replace** `internal/cli/cmd/deploy.go` with a hidden cobra stub that
   prints a fixed deprecation message to stderr and exits with code 2. The
   stub ships for exactly one release; a follow-up issue, filed as part of
   this PR, tracks its removal in the release after that.
4. **Retain** `internal/adapters/ssh/**` and `ports.RemoteExecutor`.
   `vibew tls status` depends on them (ADR is silent on this path; grep
   confirms: `internal/cli/cmd/tls.go` is the surviving consumer).
   `vibew doctor` also depends on them transitively until #1059 lands —
   that issue is unblocked by this PR but is delivered separately to keep
   the blast radius of each PR small.
5. **Rewrite** the docs enumerated in the "Docs" section below, plus
   `README.md` and `llms-full.txt`, so the canonical deploy story is
   `vibew bundle` followed by a manual `scp`/`ssh`/`docker compose up`.

### Rename strategy — single commit

The rename is done as a single atomic commit to keep `git log --follow`
useful:

```
git mv internal/app/deploy internal/app/bundle
# sed -i '' 's/^package deploy$/package bundle/' internal/app/bundle/*.go
# sed -i '' 's|internal/app/deploy|internal/app/bundle|g' \
#   $(grep -rln 'internal/app/deploy' --include='*.go')
# manual edit: bundle.go:307 header string, bundle.go's import alias if any
git add -A && git commit -m "refactor: rename internal/app/deploy to internal/app/bundle"
```

Deletions of the orchestration-only files happen in a separate commit
before the rename so `git mv` operates on a clean tree. CLI deploy command
replacement with the stub is a third commit. Three commits on one PR:

1. `chore: delete vibew deploy orchestration`
2. `refactor: rename internal/app/deploy to internal/app/bundle`
3. `feat: vibew deploy stub + deprecation message`

Plus docs and examples as further commits (PR body enumerates them).

### Stub command

`internal/cli/cmd/deploy.go` is replaced with a ~30-LOC hidden stub. Exact
shape:

```go
// NewDeployCmd returns a hidden deprecation stub for the removed
// `vibew deploy` command. It ships for one release and is removed in the
// release after that. Tracked by #<follow-up-issue>.
func NewDeployCmd() *cobra.Command {
    return &cobra.Command{
        Use:                "deploy",
        Short:              "(removed) use vibew bundle",
        Hidden:             true,
        SilenceUsage:       true,
        SilenceErrors:      true,
        DisableFlagParsing: true,
        Run: func(cmd *cobra.Command, _ []string) {
            fmt.Fprintln(cmd.ErrOrStderr(), deprecationMessage)
            os.Exit(2)
        },
    }
}

const deprecationMessage = `The "vibew deploy" command has been removed. Use "vibew bundle" to generate
deployment artifacts, then run the included deploy.sh manually. See
docs/deploy-reference.md for migration steps.`
```

Design notes:

- `Hidden: true` keeps `deploy` out of `vibew --help` but leaves it
  dispatchable so cobra does not print `unknown command "deploy"`.
- `DisableFlagParsing: true` means `--target`, `--dry-run`, etc. are
  swallowed and the same message fires — matches the PM spec.
- `Run:` (not `RunE:`) with `os.Exit(2)` directly. Root-level wiring in
  `cmd/vibewarden/main.go` maps any `RunE` error to `os.Exit(1)`, so a
  `RunE` path would produce exit 1, not 2. Direct `os.Exit(2)` is the
  cheapest way to hit the documented contract without changing the root
  wiring. Using `os.Exit` in a `Run` func is normally discouraged (no
  cleanup runs); here the process is doing nothing else, so it is safe.
- Subcommands (`status`, `logs`) are not re-registered — with
  `DisableFlagParsing: true`, any positional such as `vibew deploy status`
  is swallowed and the root deprecation message is printed. The PM spec
  accepts this behaviour.
- File: `internal/cli/cmd/deploy_stub.go`. The companion test
  `internal/cli/cmd/deploy_stub_test.go` drives the stub in-process,
  captures stderr, asserts the message text, and asserts `os.Exit(2)`
  would fire (via a `testableExit` hook or by running the test in a
  subprocess with `os/exec`; dev picks which, both are fine).
- TODO comment on the stub references the follow-up issue number filed
  during this PR: `// TODO(#NNNN): remove vibew deploy stub two releases
  after v<N>.<M>`.

A fresh follow-up issue `chore: remove vibew deploy stub` MUST be filed by
the dev during this work. The follow-up issue links back to #1051 and to
this ADR.

### Consequences

#### Breaking

- Users scripting `vibew deploy --target ...` in CI, Makefiles, or agent
  prompts see a deprecation message and exit 2. Migration recipe is in the
  new `docs/guide/bundle-to-vps.md` and in the `CHANGELOG.md` breaking-changes
  section.
- The MCP tools `vibewarden_prepare_deploy`, `vibewarden_verify_deploy`,
  `vibewarden_get_deploy_logs` remain for now; their underlying remote
  calls are unaffected by this ADR because they do not route through the
  deleted `deployapp.Service.Deploy` surface (they use their own
  adapters). Still, their purpose is now murky and a follow-up will
  rename or retire them.

#### Positive

- ~4 900 LOC removed from the codebase. Lower surface area, lower bug
  volume, fewer retros driven by deploy failures.
- `vibew bundle` is the single, testable, deterministic artifact path.
  Every future cloud target (#1052 Helm/Fly.io/k8s) builds on the same
  pure-pipeline pattern.
- Package name (`bundle`) now matches the command (`vibew bundle`) —
  removes a persistent cognitive-load source for agents and contributors.

#### Negative

- One release of a `Hidden: true` stub is friction for the CLI code
  (small) and the CLI tests (covered by a new focused test file).
- Internal users who forked `deployapp.Service.Deploy` have to migrate.
  This is intentional (see "Alternatives considered").
- ADR-080 and ADR-081 are no longer live — their code is deleted. They
  remain as historical records; future readers reaching them from a
  search should be directed to this ADR. That pointer is added via a
  short note at the top of each: "**Historical: the code described
  here was deleted by ADR-086.**" The note is the only edit permitted
  to a merged ADR; the rest of the body is left untouched per the
  "ADRs are immutable" rule in `decisions/README.md`.

### Alternatives considered

**Option (a) — immediate hard-delete, no stub.** Rejected. Users still
copy-paste `vibew deploy` commands from old docs, blog posts, retros, and
agent prompts. The one-release stub cost (~30 LOC of code + ~30 LOC of
test) is trivial compared to the UX gain from a clear deprecation
message.

**Option (b) — rename the package but keep the deploy orchestration.**
Rejected. The orchestration surface is the primary bug source (4 retros,
16 bugs). Renaming without deleting just moves the bugs to a new import
path. The rename is only worth doing in the same PR as the delete.

**Option (c) — delete orchestration but keep the package name `deploy`.**
Rejected. `vibew bundle` becomes the entrypoint and `deployapp.` as an
import alias for a bundle-only package is actively confusing. ADR-085
explicitly called out the rename as a follow-up for exactly this reason.

**Option (d) — delete AND rename AND drop the SSH adapter.** Rejected.
`vibew tls status` uses it. Deleting the adapter expands the blast radius
of this PR to TLS status as well. Kept out of scope.

**Option (e) — bundle the doctor remote-check cleanup (#1059) into this
PR.** Rejected. Blast radius. Doubling the diff of an already-large PR
makes review harder and the commit harder to revert if something
regresses. #1059 is explicitly unblocked by this PR and delivered
separately.

**Chosen: §"Decision" above — delete, rename, stub, dedicated follow-up
for the MCP tools and for #1059.**
